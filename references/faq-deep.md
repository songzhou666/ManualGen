## Q1：接力棒损坏或缺失如何恢复？

接力棒（`_baton.md`）是 ManualGen 状态机的唯一真相来源。如果接力棒损坏、内容异常或完全缺失，按以下步骤恢复：

### 步骤 1：识别损坏类型

| 损坏类型 | 表现 | 恢复策略 |
|---------|------|---------|
| 文件不存在 | 读取 `_baton.md` 返回"文件不存在" | 创建新接力棒，从 START 重新执行 |
| 状态字段异常 | 状态值不为 EXPLORE/EXTRACT/ANALYZE 等合法值 | 手动修正状态值 |
| 产物清单与实际不符 | 标记完成的产物实际不存在 | 重新生成缺失产物或修正标记 |
| 完全空白 | 文件存在但内容为空 | 按模板重新写入 |

### 步骤 2：恢复操作

**场景 A：文件不存在（最常见）**
```
AI：检测到接力棒不存在。需要初始化新接力棒：
1. 从头开始（推荐） → 状态设为 START，清除所有历史进度
2. 指定当前阶段 → 手动告知已完成的阶段，AI 设置对应状态
```

**场景 B：文件内容异常**
```
AI：接力棒当前状态异常。是否重置为最近可确认的阶段？
- 如果知道最后完成的工作 → AI 设置对应状态，继续执行
- 如果完全不清楚 → 重置为 START，从 EXPLORE 开始
```

### 相关
- 相关阶段：全阶段（入口清单）
- 相关文档：`protocols/baton-protocol.md`
- 核心原则：接力棒不存在时，不能假设任何状态，必须初始化

## Q2：大型项目（>1000 文件）如何分批处理？

ManualGen 内置分批分析机制。当项目文件数超过阈值时，AI 自动启用分批模式。

### 分批机制说明

```
总模块数: 15 个
分批策略: 每批 3-5 个模块
批次管理: _analysis_batch_index.md
```

### 各阶段的分批处理

| 阶段 | 分批方式 | 注意事项 |
|------|---------|---------|
| EXPLORE | 不批（一次性扫描全貌） | EXPLORE 必须完整，才能正确识别模块边界 |
| EXTRACT | 按模块分批提取 | 每批提取 3-5 个模块的 API/实体/规则 |
| ANALYZE | 按模块分批分析 | 每批 3-5 个模块，批次间传递上下文 |
| GAP | 不批（评估整体完整性） | GAP 需要全局视角，一次性完成 |
| WRITE | 按模块分批编写 | 无依赖模块可并行（最多 3 个并发） |

### 批次索引文件

`_analysis_batch_index.md` 管理所有批次的元信息：

```markdown
| 批次 | 模块 | 状态 | 产物文件 |
|------|------|------|----------|
| 1/3 | 客户管理, 订单管理, 商品管理 | ✅ 完成 | _analysis_batch_001.md |
| 2/3 | 库存管理, 供应商管理, 采购管理 | ✅ 完成 | _analysis_batch_002.md |
| 3/3 | 财务管理, 报表中心, 系统配置 | 🔄 进行中 | _analysis_batch_003.md |
```

### 相关
- 相关阶段：ANALYZE
- 相关文档：`artifacts/template-artifacts.md`（_analysis_batch_index.md 模板）
- 分批规则：每批不超过 5 个模块，保证分析深度

## Q3：JUDGE 阶段审核不通过怎么办？

JUDGE 阶段由子 Agent 进行独立盲审。如果审核不通过（综合评分 < 75分 或触发阻断），按以下流程处理。

### 判定类型及应对

| 判定结果 | 含义 | 修复策略 |
|---------|------|---------|
| **DONE**（≥85分） | 通过，可交付 | 流程结束，输出最终手册 |
| **CONDITIONAL PASS**（75-84分） | 有条件通过，需微调 | 针对扣分项微调后重新判定 |
| **FAIL + WRITE** | 不通过，需返回编写阶段 | 读取 _audit.md 的阻断项和扣分点，返回 WRITE 修复 |
| **FAIL + FAILED** | 严重不通过，流程终止 | 需人工介入，评估是否重新生成 |

### 修复流程

```
审核不通过
    ↓
读取 _audit.md 中的"待修复问题清单"
    ↓
逐项检查阻断项和扣分点
    ↓
返回对应阶段修复：
  - 结构缺失 → 返回 WRITE
  - 流程图缺失 → 返回 WRITE（补充 Mermaid 图）
  - 隐私违规 → 返回 WRITE（脱敏后重写）
  - 术语不一致 → 返回 REFINE
    ↓
修复后更新接力棒，重新进入 JUDGE
    ↓
盲审通过 → DONE
```

### 相关
- 相关阶段：JUDGE
- 相关文档：`SKILL.chunks/chunk-05-audit-judge.md`
- 相关文档：`quality-control/00-quality-system.md`（6 维度评分标准）

## Q4：WRITE 阶段如何并发写多个模块？

ManualGen 的 Master Controller 支持在 WRITE 阶段通过子 Agent 并行编写模块。

### 并发规则

| 条件 | 是否可并行 | 示例 |
|------|-----------|------|
| 模块间无数据依赖 | ✅ 可并行（最多 3 个） | 客户管理 + 系统配置 |
| 模块间有数据依赖 | ❌ 不可并行 | 订单管理依赖商品管理 |
| 模块间有角色共享 | ✅ 可并行 | 只读模块 + 报表模块 |
| 模块共享同一数据库表 | ⚠️ 谨慎并行 | 需要 Resolver 协调冲突 |

### 实现机制

```
Master Controller
    ├── 子Agent 1 → 写"客户管理"模块
    ├── 子Agent 2 → 写"订单管理"模块
    └── 子Agent 3 → 写"商品管理"模块
        ↓ 所有子Agent完成
    REFINE 阶段（逐模块精炼补全）
```

### 注意事项
- 并发写模块时，每个子 Agent 不传技术上下文（API 路径、数据库表名等），只传模块名和业务场景
- 技术细节通过 Master Controller 统一管理
- 并发写完后必须进入 REFINE 阶段逐模块精炼

### 相关
- 相关阶段：WRITE
- 相关文档：`agents/00-master-controller.md`

## Q5：跨 Session 续跑时需要注意什么？

ManualGen 支持跨 Session 续跑（关闭对话后重新打开，状态自动恢复）。

### 续跑前提条件

| 条件 | 说明 | 检查方式 |
|------|------|---------|
| 接力棒存在 | `_baton.json` 文件存在且状态有效 | AI 入口清单检查 |
| 前置产物完整 | 已完成的阶段产物都存在 | AI 逐个检查产物文件 |
| 项目路径不变 | 续跑时自动沿用 baton.meta.project_path（无需用户确认） |

### 续跑流程

```
对话重新打开
    ↓
用户激活 ManualGen
    ↓
AI 执行入口清单：
  1. 读取接力棒 → 获取当前状态
  2. 检查前置产物存在性
  3. 输出 "当前状态：{阶段}，下一步：{操作}"
    ↓
从断点继续执行
```

### 常见问题

**Q：续跑时发现前置产物不完整怎么办？**
A：AI 会列出缺失的产物文件。如果缺失的产物不影响当前阶段（如之前的探索报告被清理），AI 可以跳过检查继续执行。如果关键产物缺失（如缺少分析报告但当前在 WRITE 阶段），AI 会返回前一阶段重新生成。

**Q：续跑时接力棒状态与产物不一致怎么办？**
A：以实际产物为准。如果接力棒标了"WRITE 完成"但 _modules/ 目录为空，AI 会重置状态为 WRITE 重新执行。

### 相关
- 相关阶段：全阶段
- 相关文档：`protocols/baton-protocol.md`（续跑流程节）

## Q6：如何自定义输出格式或模板？

### 模板自定义

ManualGen 的输出格式由 `templates/user-manual.md` 控制。修改该文件即可改变最终手册的章节结构。

```markdown
支持的修改：
- 新增章节 → 在模板中添加新的章节标题和结构
- 调整顺序 → 重新排列章节顺序
- 修改格式 → 调整 Markdown 结构、表格格式等
```

### 自然语言定制

在启动 ManualGen 时，用户可通过自然语言直接指定偏好（无需等 AUTO_REVIEW 阶段），AI 在后续 WRITE + TODO 阶段优先应用：

AI 会把用户给出的偏好写入 baton.custom_preferences 对象，在 WRITE 阶段 Module-Writer、TODO 阶段 AI 解路径时都会读取并应用。

### 相关
- 相关阶段：启动时输入 → WRITE → TODO（全流程不中断）
- 相关文档：`templates/user-manual.md`
- 相关文档：SKILL.md 中的"定制化指南"章节

## Q7：隐私保护规则是否可放宽？

**绝对不可放宽。** 隐私保护是 ManualGen 的硬性阻断条件，不是建议。

### 为什么不可放宽

| 原因 | 说明 |
|------|------|
| 阻断级别 | 违反隐私保护 → 该阶段产物无效 → 必须重写 |
| 扫描机制 | AUDIT 阶段会扫描所有产物中的密码/密钥/IP |
| 发现即阻断 | 即使一个环节通过，整体审核也不通过 |
| 用户要求也不可以 | 即使被用户要求展示，也**不得展示**敏感信息 |

### 常见违规场景

| 场景 | ❌ 错误 | ✅ 正确 |
|------|--------|--------|
| 配置文件密码 | `NEO4J_PASSWORD = "msl666666"` | `NEO4J_PASSWORD = "****"` |
| 数据库连接 | `Server=192.168.1.100;Password=P@ssw0rd` | `Server={服务器地址};Password=****` |
| API Token | `Bearer eyJhbGciOiJIUzI1NiIs...` | `Bearer {token}` |
| 账号密码 | `admin / admin123` | `{账号} / {密码}` |

### 相关
- 相关文档：`privacy/privacy-notice.md`
- 相关文档：`SKILL.chunks/chunk-06-privacy-security.md`
- 执行方式：每个阶段结束时执行隐私自查清单

## Q8：产物目录可否自定义？

**产物目录不可自定义。** 所有 ManualGen 的产物统一放在 `{项目路径}/.agent/harness/` 目录下。

### 为什么固定

- **接力棒依赖**：AI 自动通过产物路径前缀寻找前置文件，固定路径确保续跑时能正确找到
- **清理策略**：固定路径便于管理，AI 可识别哪些是 ManualGen 产物
- **多项目隔离**：`{项目路径}/` 前缀天然隔离不同项目
- **隐私保护**：`.agent/harness/` 路径建议加入 `.gitignore`，避免产物提交到公开仓库

### 目录结构（v6）

```
{项目路径}/.agent/harness/
├── _baton.json                # 接力棒（v6 改为 JSON，含 18 阶段进度+批进度+回灌状态）
├── _kb/                       # 知识底座（六层产物）
│   ├── L0_skeleton.json       # L0 骨架（模块/角色/依赖）
│   ├── L1_modules/*.json      # L1 模块（每批 2-3 模块）
│   ├── L2_pages/*.json        # L2 页面
│   ├── L3_regions/*.json      # L3 区域
│   ├── L4_functions/*.json    # L4 功能
│   ├── L5_details/*.json      # L5 细节（ENTITY/ROLE/ELEMENT/字段详情/权限矩阵/按钮状态）
│   ├── graph/                 # 知识图谱（6 个 JSON）
│   │   ├── _nodes.json        #   8类节点归一化
│   │   ├── _triples.json      #   三元组
│   │   ├── _evidence.json     #   证据+反向索引
│   │   ├── _snakes.json       #   跨模块概念链
│   │   ├── _layer_index.json  #   层级完成度
│   │   └── _quality.json      #   质量评估汇总
│   ├── _gap_analysis.md       # 完整性评估
│   ├── _auto_decisions.md     # AI 自主裁决记录（替代 v5 人工确认）
│   └── _backfill_log.md       # 增量回灌日志
├── _refine_log.md             # 精炼日志
├── _reference_check.md        # 一致性检查报告
├── _integration.md            # 整合手册（中间产物）

├── _todo_list.md              # TODO 列表
├── _todo_resolution.md        # TODO 解决报告

├── _modules/*.md              # WRITE 阶段模块文档
└── _appendix/                 # INTEGRATE 阶段附录
    ├── appendix-B-permission-matrix.md
```

## Q9：一个项目可以多次运行 ManualGen 吗？

**可以。** ManualGen 的接力棒机制支持增量更新。

### 增量更新机制

| 运行次数 | 行为 | 产物变化 |
|---------|------|---------|
| 第 1 次 | 完整流程（EXPLORE 到 JUDGE） | 所有产物从零创建 |
| 第 2 次（代码未变） | 重新生成（覆盖产物） | 所有产物重新生成 |
| 第 2 次（代码有小变更） | 增量更新 | 仅变更模块重新分析 |
| 第 2 次（项目路径不同） | 独立项目 | 完全独立，互不影响 |

### 增量更新的工作方式

```
步骤 1: AI 读取接力棒，发现已有历史产物
步骤 2: 对比代码变更，识别受影响模块
步骤 3: 仅重新分析受影响的模块
步骤 4: 未变更模块保留原有内容
步骤 5: 整合后重新输出手册
```

### 注意事项

- **不自动覆盖旧手册**：新运行会完整产出，旧手册不会被自动删除
- **同路径覆盖**：如果直接运行完整流程，同项目路径下的产物会被覆盖
- **接力棒重置**：新项目路径下没有接力棒时，从 START 开始
- **⚠️ 多 Skill 并行冲突（平台级约定）**：ManualGen、scout、parse 等 harness 型 Skill **共用** `{项目路径}/.agent/harness/_baton.json` 命名空间。**同一项目请勿并行运行多个 harness 型 Skill**，否则会互相覆盖接力棒导致断点错乱。若必须先后使用，务必在切换 Skill 前将接力棒归档（改名保存），或使用不同项目目录。这是平台 harness 共享区约定，非 ManualGen 缺陷。

### 相关
- 相关阶段：START（全阶段）
- 相关文档：`protocols/baton-protocol.md`

## Q10：如何验证 ManualGen 输出的质量？

ManualGen 通过 10 维度审核体系（AUDIT）+ JUDGE 模块级盲审两层机制保障输出质量。

### 第一层：10 维度自评（AUDIT 阶段）

原 6 维（权重合计 80%）：

| # | 维度 | 权重 | 检查内容 |
|:-:|:-----|:---:|:---------|
| ① | 手册结构完整性 | 20% | 是否包含前置说明、基础操作、核心功能、全流程、异常处理、权限矩阵、附录 |
| ② | 流程图质量 | 16% | 分类绘制、用户语言、链路完整、标注清晰、一一对应 |
| ③ | 去技术化合规性 | 12% | 无 API 端点、无 HTTP 代码、无技术堆砌、基于界面操作 |
| ④ | 操作可执行性 | 12% | 功能简介、权限说明、前置条件、分步操作、字段说明、风险提示 |
| ⑤ | 角色隔离与权限清晰 | 12% | 每模块标注角色、全局权限矩阵、权限流转图、角色边界清晰 |
| ⑥ | 异常覆盖完整度 | 8% | 报错汇总、操作异常处理、边界问题说明、紧急处理流程 |

⑦⑧ 为保留的引用维度（权重 0%，仅作 REFERENCE_CHECK 的 PASS/FAIL 条件）：快速入门可用性、术语风格统一性；**v6 真正新增的 2 个计分维度是 ⑨⑩（合计 +20%）**：

| # | 维度 | 权重 | 检查内容 |
|:-:|:-----|:---:|:---------|
| ⑨ | 图谱交叉验证率 | 10% | cross_verified_nodes_pct×10（节点双源验证比例） |
| ⑩ | Snake 完整性 & 覆盖率 | 10% | min(snakes_discovered/目标数,1)×10 − incomplete×0.5 |

### 第二层：JUDGE 盲审

```
盲审规则：
- 子 Agent 与写作者完全隔离上下文
- 不知道谁写的、不知道分析过程
- 仅基于产物本身做独立判断
- 判定结果不可被写作者推翻
```

### 质量等级

| 综合评分 | 等级 | 含义 |
|---------|------|------|
| ≥90 分 | A | 优秀，可直接发布 |
| 75-89 分 | B | 良好，需微调后发布 |
| 60-74 分 | C | 需整改后重新审核 |
| <60 分或阻断 | D | 不合格，返回 WRITE 重写 |
