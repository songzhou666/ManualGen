## 五大检查维度

### 0. 跨模块端到端闭环检查（新增！）

**核心思路**：检查一个业务请求从触发到完成的完整链路是否在所有模块间畅通。

**检查方法**：
1. 识别"用户旅程"级别的跨模块业务流程
2. 对每个旅程，检查每一步的来源模块和目标模块
3. 标注每个环节的状态："✅ 已实现 / ⚠️ 部分实现 / ❌ 缺失"

| 用户旅程 | 步骤1 | 步骤2 | 步骤3 | 步骤4 | 整体状态 |
|---------|-------|-------|-------|-------|---------|
| 用户下单→付款→发货→确认 | 创建订单(订单模块) ✅ | 付款(支付模块) ✅ | 发货(物流模块) ⚠️ | 确认收货(订单模块) ❌ | ⚠️ 部分闭环 |

**检查类型**：
- 端到端流程：一个完整业务流程的所有节点是否都有对应的模块功能？
- 跨模块数据流转：模块A产出的数据，模块B是否能正确消费？
- 状态同步：一个跨模块流程中，各模块的状态是否同步更新？
- 异常回滚：跨模块流程中，一个环节失败，上游是否能回滚？

**输出**：
- 跨模块流程完整性清单（含每个环节的状态标记）
- 跨模块断点列表（流程断裂的位置和原因）

### 1. 功能完整性检查

| 检查类型 | 检查项 |
|----------|--------|
| CRUD检查 | 新增是否配编辑/详情/删除？有列表是否有详情？ |
| 入口出口 | 按钮是否有对应操作？模态框是否有取消/关闭？ |
| 工作流检查 | 审批流是否有终态？驳回是否可重新提交？ |
| 前后端匹配 | 前端路由和对应API是否都存在？ |

**分级**（P0~P3 四级，与 phase-protocol.md:20 检查点对齐）：
- P0：功能完全未实现（模块/页面/功能缺失，或 API 与页面均缺失）
- P1：功能部分实现（有页面无 API / 有 API 无页面 / 断链 / Snake 不完整）
- P2：缺少异常处理或细节（无边界条件/失败反馈/字段或权限覆盖不足）
- P3：完善性建议（术语不统一/表述可优化/非阻断优化项，不影响交付）

### 2. 数据流完整性检查

- 每个数据的生产者是否明确？
- 每个数据的消费者是否能获取到数据？
- 数据流路径是否存在断点？
- 必填字段的数据来源是否明确？
- 关联数据的级联操作是否完整？

### 3. 异常处理完整性检查

- 每个操作是否有失败时的反馈？
- 必填字段为空/超长/格式错误是否有验证？
- 非法状态转换是否有拦截？
- 权限不足时是否有提示？

### 4. 项目形状综合分析

- **全景图**：所有模块 + 边界 + 关系的完整视图（Mermaid）
- **功能矩阵**：模块 × 功能类型 × CRUD覆盖度
- **质量仪表盘**：各维度评分汇总
