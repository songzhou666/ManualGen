## §AUDIT（阶段 15）

**职责**：对照 10 维质量体系（含 v6 新增 2 个图谱维度）对最终整合稿做初次评分，准备自评报告 + TODO 清单。
> 注意：AUDIT 是主控自评（快速发现问题）；JUDGE 阶段才拉起独立子 Agent 做真正盲审。

### 执行流程
1. 加载 `_integration.md`（完整手册文件）+ `graph/_quality.json`（图谱质量分）
2. 对照下方 10 维度检查清单逐项打分（6 个原维度 + 2 个图谱维度 + 2 个引用维度）
3. 生成 `_audit.md` 输出报告 + 同步生成 `_todo_list.md`（§TODO 输入）

### 🚨 强制执行规则（违反=审核无效）

**规则1** → 不得使用"五星评分"、"★☆☆☆☆"等简化评分方式
- 必须按下方 10 维度表格逐项打分，每项给出0~100的具体数值
- ❌ **禁止** `★★★★★` 这种评级
- ✅ **必须** 用 `85/100` 这种具体数值

**规则2** → 每个维度的评分必须附上**具体理由**
- 正例：`④ 操作可执行性：65/100 → 原因：缺少字段说明表，操作结果描述不完整`
- 反例：`可执行性：良好 ✅`（太模糊，无效）

**规则3** → 阻断检查**必须逐项列出结果**，不得跳过
- 必须输出完整的阻断检查表，每项标注✅通过或❌阻断

**规则4** → 评分必须基于产出物的**实际内容**，而非"模板声称"
- 不要只看模板里写了什么，要看**最终产物里实际有什么**
- 例如：如果 `_integration.md` 中没有流程图，即使模板声称"包含流程图"，评分也应扣分

**规则5** → 综合评分计算公式必须可追溯
- 每维度分 × 权重 的加权和 = 综合分
- 必须在 `_audit.md` 中展示计算过程

**职责**：
1. 从 `_todo_list.md` 读取所有 TODO 条目（AUDIT 生成 + AUTO_REVIEW 第四清单 + REFINE 遗留 fail）

4. 无法解决的 P0 必须给出 BLOCKER 说明（影响范围·建议用户手动处理的具体步骤）。

### AI 自动解决规则矩阵（6 类高频 TODO 自动解）

| TODO 类型 | 检测关键词 | AI 自动解路径 | 写回位置 | 熔断（单 TODO≥3 次尝试仍失败） |
|----------|-----------|--------------|---------|-------------------------------|
| T1 字段说明表缺必填/示例 | "字段表缺必填" / "缺示例" | 从 ENTITY.fields JSON + validation JSON 回填 6 列（字段名/类型/必填/规则/默认/示例） | 对应模块文档 §字段说明表 | BLOCKER：该字段只写 ⚠️ 推断值 |
| T2 角色权限 ❔ 未知 | "权限：未知" / "❔" | 从 @PreAuthorize + router.meta.roles + 菜单 v-if 三重证据聚合，填 ✅/⚠️/❌ | 附录 B 权限矩阵 + 对应模块文档的「角色说明」 | BLOCKER：保留 ❔ 并附录 C 增列 |
| T3 流程图缺分支/驳回 | "流程图缺驳回" | 用 WRITE 阶段 Module-Writer 的标准 4 走向模板：正常→分支→驳回→终止；读取操作步骤提取异常分支 | 对应模块文档 §流程图 Mermaid | BLOCKER：流程图只画正常走向，加 ⚠️ 文字说明 |
| T4 术语不一致 | "术语不一致" | 从 REFERENCE_CHECK 的术语表选「出现频次最高」作为统一写法；批量 replace 所有 `output_user_manual/_modules/*.md` | 所有 `output_user_manual/_modules/*.md` + 主手册 | BLOCKER：只改高频模块，附录 C 列差异项 |
| T5 Snake 缺节点/断边 | "Snake 缺节点" / incomplete | 回灌 L4/L5 那两个节点所在批次，重跑 graph Step5 Snake 发现；再推进 INTEGRATE 重写附录 D | graph/_snakes.json + 附录 D | BLOCKER（≥2 次仍 incomplete）：Snake 保留 incomplete 并附录 C 列 Top |
| T6 证据不足的 HUMAN_REVIEW 节点 | "待复核" / requires_human_review | 再尝试 1 次：只读对应源文件局部精读（只看 handler/注解 1 个），≥2 条证据自动过；否则附录 C 保留 Top | _auto_decisions.md + 附录 C 第四清单 | BLOCKER：直接列附录 C，不再反复 |

### 执行流程

```
Step 1: 读 _todo_list.md，按优先级(P0>P1>P2>P3)排序
Step 2: _todo_list.md 顶部 cursor = 0（处理游标，记录已处理到第几条）
Step 3: for each TODO in 排序后列表:
   3a. todo_attempts[该TODO.id] = 0
   3b. while 尝试解决中:
         - 走上方规则矩阵（类型→解路径）
         - todo_attempts[id] += 1
         - ≥3 次仍不行 → BLOCKER 记录，跳出
         - 成功 → 标记 RESOLVED，跳出
   3c. 原子写对应目标文件 + 更新 _todo_list.md 顶部 cursor += 1
   3d. 累计 BLOCKER ≥5 且 P0≥2 → 触发 1 次全局告警（不阻断流程）
Step 4: 输出 `_todo_resolution.md`（含每条：TODO ID/原文/状态(RESOLVED/BLOCKER)/理由）
```

### 第 1 步：拉起独立子 Agent 进行盲审（强制 — 核心质量门）

这是最关键的一步。**你必须拉起一个全新的子 Agent 来做审核，不得自己审核自己。**

使用 `Task` 工具的 `general_purpose_task` 子 Agent，query 参数中只传入以下信息（严格按 `agents/14-judge-agent.md` §启动头）：

你与之前所有文档生成阶段完全隔离：
- 你不知道文档是谁写的、经历了 L0~L5 哪 6 层、有没有做过 REFINE/AUDIT/TODO
- 你不能看源码 / 不能看 .agent/harness/_kb/* / 不能看 graph JSON / 不能联网

你唯一能读取的输入：

2. 模块级打分规则（见 agents/14-judge-agent.md §打分标准）

请按以下步骤执行：

6 维度检查清单（模块级·每模块独立打分）：
① 手册结构完整性（满分25分）：7 个章节（前置说明/基础操作/核心功能/业务闭环/异常处理/权限角色/附则）是否齐全。7全有=25，缺1个=20，缺2个=10(阻断)，缺≥3个=0(阻断)
② 流程图可用性（满分20分）：Mermaid 流程图≥3个、含正常+驳回+终止走向。无Mermaid=0(阻断)，ASCII替代=10
③ 去技术化合规性（满分15分）：无API端点表/HTTP代码块/后端名/技术术语堆砌。发现任意1项=0(阻断)
④ 操作可执行性（满分15分）：抽3模块验证 功能简介/权限/前置/分步/字段/结果/风险 7件套。7全=15，缺1=12，缺2=8，缺≥3=0
⑤ 角色隔离与权限清晰（满分15分）：每模块角色标注+全局权限矩阵+流转图。5项全=15，缺1=10，缺≥2=0
⑥ 异常覆盖完整度（满分10分）：报错汇总/操作异常/边界说明/紧急流程。4项全=10，缺1=5，缺≥2=0

阻断条件（任意一条=该模块不通过）：
- 结构完整性缺≥2个模块 → 阻断
- 无任何Mermaid流程图 → 阻断
- 发现API/HTTP/技术名词堆砌 → 阻断
- 发现任何"详细操作请参阅 xxx.md"或`output_user_manual/_modules/`引用 → 阻断（必须完整内联）

### 第 2 步：判定（模块级 · v6 对齐 phase-protocol §17 与 14-judge-agent）

```
PASS_rate = count(per_module_scores[*].score ≥ 70) / N
if PASS_rate ≥ 0.70:
  → 全局 PASS → DONE（即使有 <70 的模块，只要 ≤30% 且 ≤2 次重试就放行）
else:
  → 找 TOP_M 个最低分模块（M ≤ max(3, 0.1*N)）
  → 每个不合格模块且 retry_count[module] ≤ 2:
       → 只重做该模块：baton.rework.write_rerun_modules.append(module_id)
       → baton.meta.state = WRITE & baton.meta.sub_state="RERUN_MODULES"（按 chunk-04 §5.3 只重写该模块）
  → 不合格模块且 retry_count[module] ≥ 3:
       → 不再重写，最终文档该模块末尾加 ⚠️：「该模块盲审第3次仍不合格，质量参考评分 X/100，请用户人工复核」
       → 附录 C Top 清单新增该模块整体条目
```

全局综合分（仅供用户查看·不影响 PASS/FAIL 阈值）：
```
综合分 = per_module_scores 平均分 × 0.7 + 附录B/C/D/E质量分 × 0.2 + 概述/通用章节分 × 0.1
```

### 第 3 步：输出与落盘

- 子 Agent 返回 `per_module_scores` JSON + 人话报告，主控将其写入 `_judgment.md` 作为最终判定报告（格式见 `agents/14-judge-agent.md` §输出格式）
- 打回的模块按 `agents/12-refiner-agent.md` 流程修复后，重跑 `INTEGRATE → AUDIT → JUDGE` 只针对该模块（不重跑其他模块）

### 修复流程（v6 模块级，不再全量重写）
```
JUDGE 打回模块M → WRITE(只重做M) → INTEGRATE(重新整合M) → AUDIT(重审M) → JUDGE(重判M)
```
- 禁跳过中间步骤
- 最多 2 次重试（模块级 retry_count 累计）
- retry ≥ 3 → 该模块加 ⚠️ 降级交付（DONE 不阻塞，附录 C 列 Top）

### 产物
`_judgment.md`（per_module_scores + PASS/FAIL + rerun_modules 清单）
