# 附录 F 模板：未覆盖模块/功能清单（Uncovered Scope List）
> v6.2 强制产物：core_priority 模式必须生成；full 模式无未覆盖项时也要产出并注明。
> 数据来源：`baton.batch.skipped_modules` + `_kb/L1_index.json` 全量模块对照。
> 生成阶段：INTEGRATE（见 `agents/05-integrator-agent.md` §F 与 §四 自检）。

## 使用说明
- **full（全量）模式**：正常情况此清单为空；若仍存在未覆盖模块/功能（如质量门未通过被记入 incomplete_batches 的批），必须在此显式披露并给出回灌建议，禁止静默缺失。
- **core_priority 模式**（用户显式点名模块范围）：未覆盖项必须与此清单完全一致（与 `baton.batch.skipped_modules` 逐一对照），禁止多列或漏列。
- 未覆盖 = 仅停留在背景 L2 深度 / 未含操作级内容 / 未过质量门，三种情况都要写清原因。

手册未覆盖模块：{MOD_007 系统设置, ...}（仅停留在背景 L2 深度，未含操作级内容）

## 与全量覆盖铁律的一致性声明

- 全量模式下，`batches_done == batches_total` 且各层质量分达阈值，未覆盖清单为空 → 视为全量覆盖。
- 存在 `incomplete_batches`（质量门未过的批）→ 即使批次计数完成，也必须在本清单披露并列入附录 C Top 未决项，且 INTEGRATE 前必须回灌。
- core_priority 模式下，未覆盖模块数 + 覆盖模块数 = `L1_index.json` 全量模块数，逐项可溯源。
