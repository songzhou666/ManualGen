# ManualGen 可视化进度反馈协议

> 定义标准化的进度展示格式，在每个阶段切换时自动输出。
> 让用户直观了解当前进度、已完成工作和剩余工作。

---

## 二、进度百分比计算规则

| 阶段 | 0% → 100% 的判定依据 |
|------|----------------------|
| EXPLORE | 完成项目架构扫描 + 模块识别 + 数据依赖链 |
| EXTRACT | 完成 API/数据库/页面 三类信息提取 |
| ANALYZE | 完成流程分析 + 状态机 + 边界定义 + 数据流全景图 |
| GAP | 完成 CRUD 检查 + 数据流检查 + 异常处理检查 + 项目形状报告 |
| CONFIRM | 已展示摘要 → 100%（等待用户响应期间维持 100%） |
| RESOLVE | 完成冲突扫描 + 冲突解决 + 报告输出 |
| WRITE | 已完成模块数 / 总模块数（如 3/5 = 60%） |
| REFINE | 被标记的模块100%精炼完成 |
| REFERENCE_CHECK | 术语一致性检查+交叉引用检查+风格统一全部完成 |
| INTEGRATE | 已完成模块收集 + 组装 + 交叉引用 |
| AUDIT | 完成各卷审核 + 汇总评分 |
| TODO_RESOLVE | 完成 TODO 扫描 + 分解决策 + 报告输出 |
| JUDGE | 完成判定 + 输出最终报告 |

## 三、更新时机

### 3.1 必须输出的时机

| 时机 | 输出内容 |
|------|----------|
| 阶段开始时 | 完整进度栏（含当前阶段标记为 ▶） |
| 阶段完成时 | 阶段完成提示 + 更新后的完整进度栏 |
| CONFIRM 阶段 | 详细摘要（模块清单 + 空缺 + 评分） |
| 用户主动询问时 | 输出最新进度栏 |
| 流程结束时（DONE） | 最终进度栏（全部 100% ✅）+ 最终报告 |

### 3.2 输出规则

1. 每个阶段开始时，在回复第一行之后立即输出进度栏
2. 阶段完成时，在回复末尾输出阶段完成提示
3. 进度栏必须包含所有 11 个阶段的状态
4. 已完成阶段标记 ✅，当前阶段标记 ▶，未开始标记 ⏳

## 四、整合到阶段协议

### 4.1 通用执行流程更新

原流程：
```
Step 1: 读取接力棒 → Step 2: 读取前置产物 → Step 3: 执行阶段任务 → Step 4: 自检清单 → Step 5: 更新接力棒 → Step 6: 进入下一阶段
```

更新为：
```
Step 1: 读取接力棒 → Step 2: 输出进度栏（阶段开始时） → Step 3: 读取前置产物 → Step 4: 执行阶段任务 → Step 5: 自检清单 → Step 6: 更新接力棒 → Step 7: 输出阶段完成提示 → Step 8: 进入下一阶段
```

### 4.2 CONFIRM 阶段特殊处理

CONFIRM 阶段必须使用详细摘要格式，并包含：
- 模块完成列表（✅/⏳/❌）
- 空缺清单（P0/P1/P2）
- 质量评分
- TODO 标记数量
- 确认按钮（文字提示）

## 五、终端兼容

### 5.1 纯文本模式

当无法使用 ANSI 颜色时，使用纯文本进度条（Block 字符）：

- `[████████░░]` 表示 80%
- 使用 `█` (U+2588) 表示已完成部分
- 使用 `░` (U+2591) 表示未完成部分

### 5.2 富文本模式

在支持 HTML 的环境（如某些 Web 客户端）：
- 使用颜色标记：✅ 绿色、⏳ 黄色、▶ 蓝色
- 使用加粗标记当前阶段
